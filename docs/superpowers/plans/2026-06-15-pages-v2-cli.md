# Pages v2 CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a v2-only `pages` CLI that logs in through `pages-auth`, stores credentials safely, binds projects with `.pages.json`, and calls only the `*.pages.xd.team` v2 API/Auth surfaces.

**Architecture:** Add a new workspace package `apps/pages-cli` with a small Node.js ESM CLI. The CLI owns local UX, config, credentials, project binding, request signing headers and deterministic artifact hashing; `pages-api` remains the control plane and `pages-auth` remains the OAuth/CLI-login authority. Production and staging endpoints are fixed and cannot be overridden; custom endpoints are allowed only for localhost / loopback v2 development.

**Tech Stack:** Node.js `>=22.12.0`, ESM, built-in `node:test`, `node:fs`, `node:path`, `node:crypto`, `node:child_process`, Fetch API.

---

## Scope Notes

- Do not stage or commit `docs/xd-sso.md`.
- Do not change v1 `apps/server` behavior.
- The CLI must reject `workers.xd.team` and must not send tokens/access keys to arbitrary third-party hosts.
- `.pages.json` is project binding metadata only; it must never contain token, access key, cookie, Cloudflare resource id, SSO secret or capability.
- Browser login and `--access-key` login must both work.
- WFP upload is M5; for M4 `pages deploy` computes a deterministic content hash and creates the M3 deployment record.

## File Map

- Create `apps/pages-cli/package.json`: workspace package and `bin.pages`.
- Create `apps/pages-cli/src/main.js`: executable CLI entrypoint.
- Create `apps/pages-cli/src/args.js`: minimal argument parser.
- Create `apps/pages-cli/src/config.js`: environment registry, endpoint safety validation, profile config.
- Create `apps/pages-cli/src/project-config.js`: `.pages.json` read/write/validation.
- Create `apps/pages-cli/src/secret-store.js`: OS secret store adapters plus secure fallback checks.
- Create `apps/pages-cli/src/profile.js`: profile selection and credential read/write.
- Create `apps/pages-cli/src/api-client.js`: JSON request helper, auth header, idempotency key.
- Create `apps/pages-cli/src/login.js`: access-key login and browser polling login.
- Create `apps/pages-cli/src/artifact.js`: deterministic file/directory hashing and artifact-kind inference.
- Create `apps/pages-cli/src/commands.js`: `login`, `deploy`, `status`, `rollback`, `open`, `env` command handlers.
- Create focused `*.test.js` files next to modules.
